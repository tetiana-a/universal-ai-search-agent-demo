# n8n для AURELIUS — опциональная автоматизация, не обход ограничений соцсетей

## Что здесь готово

`aurelius-readonly-daily-report.json` — импортируемый **выключенный по умолчанию** workflow:
Schedule 09:00 Europe/Prague → GET AURELIUS campaigns → сводка → личное Telegram-сообщение владельцу.

Это только сбор отчёта. **Workflow не публикует объявления, не отправляет рассылки третьим лицам и не заменяет проверку согласий администраторов.**

## Подключение в n8n Cloud или на лицензированном self-hosted

1. Создайте n8n-аккаунт и импортируйте workflow через **Import from File**.
2. Откройте шаг «Read AURELIUS campaigns»: настройте **HTTP Header Auth** credential с Name `x-scout-key` и Value — `SCOUT_ADMIN_KEY` из Vercel. Не храните ключ в JSON.
3. В шаге «Send owner report» задайте **Telegram API** credential с токеном действующего AURELIUS-бота; укажите настоящий ID личного чата владельца вместо `REPLACE_WITH_OWNER_TELEGRAM_CHAT_ID`.
4. Исполните вручную и проверьте отчёт. Только после этого активируйте Schedule Trigger.
5. Убедитесь, что время и часовой пояс подходят клиенту. Vercel уже имеет собственные `/api/scout/cron` и `/api/campaigns/cron`: **не дублируйте планирование/отправку публикаций** в n8n.

**Никогда не включайте Telegram Trigger (webhook) в n8n с токеном @AURELIUS8_bot:** Telegram поддерживает единственный webhook, и регистрация другого прервёт существующее голосовое управление Vercel. Отправляющий Telegram-узел этого не делает.

## Когда действительно нужен n8n

- Напоминания администраторам, подготовка предложений, передача на ручное согласование.
- Интеграции Google Sheets, CRM и платёжных подтверждений.
- Обработка ошибок, оповещения владельцу, выгрузка доказательств публикаций.
- После появления большой сети партнеров — отдельные гарантированные очереди, ограничение частоты и ручные шлюзы.

n8n **не** создаёт права публикации в Facebook Groups, Instagram, TikTok и чужих Telegram-группах. Для автопостинга используйте официальные API собственных аккаунтов/каналов или разрешения владельцев. Meta Groups API закрыт для такого применения.

## Хранение

Сейчас AURELIUS использует Upstash Redis через `UPSTASH_REDIS_REST_URL/TOKEN`, база уже работает. Для MVP её достаточно: группы, кампании, очередь, согласования и журнал.

Для коммерческого масштаба и 14-дневного аудита рекомендовано перенести транзакционные сущности в PostgreSQL (Supabase/Neon/managed Postgres): `campaigns`, `groups`, `campaign_targets`, `permissions`, `placements`, `proofs`, `events`; Redis оставить для временных блокировок, лимитов и короткой очереди. Медиа — в S3/R2/Supabase Storage с разрешениями и сроками хранения.

Не включайте платный n8n или Postiz до завершения теста одного разрешённого Telegram-канала. Бесплатная/self-hosted Community n8n лицензируется отдельно: проверьте Sustainable Use License перед клиентской коммерческой эксплуатацией.
